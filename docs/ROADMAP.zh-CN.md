# 改进路线图（中文版）

以下是建议的改进项，按对 FYP 演示和实际可行性的价值排序。每项对应的具体待处理问题见 [`AUDIT.zh-CN.md`](AUDIT.zh-CN.md)。

## 1. 先让系统可靠

| 事项 | 原因 |
|---|---|
| **每次推送都运行 CI。** GitHub Actions 运行 `npm ci`、`typecheck`、`lint` 和 `test`。 | 能提前拦截类似测试脚本失效、Windows 版 lockfile 之类的回归问题，避免它们进入构建。 |
| **带演示账号的种子脚本。** `prisma/seed.ts` 创建管理员、一个已认证房东（含一处已通过认证的房产和两个房间），以及处于各个生命周期阶段的租客。 | 一条命令即可完成演示环境搭建。评审者无需经过注册和 KYC 就能看到每个流程。 |
| **为涉及资金和签署的路径编写路由级测试：** 定稿、签署、批准签署证明、批准押金、押金结算和定时任务。使用一次性 Postgres（Docker 或 Neon 分支）。 | 这些流程的 bug 会造成经济损失或法律后果。目前只测试了纯辅助函数。 |
| **身份证件私有存储。** 使用经过鉴权的 Cloudinary 上传，并通过带权限校验的接口提供访问。 | 这是最大的隐私缺口（PDPA 2010）。 |
| **把管理员引导改为脚本。** | 去掉每次页面请求的数据库查询，让页面重新具备可缓存性。 |

## 2. 让框架更易扩展

- **共享路由辅助函数。** 在 `src/lib/authz.ts` 中新增 `requireUser()`、`requireRole()`、`requireLandlordTenancy(id)` 和 `requireTenantTenancy(id)`。它们返回带类型的记录或统一的 `{ error }` 响应，替代约 60 处手写的会话与归属检查。
- **统一的校验方式。** 用 zod 通过一个小型 `parseBody(request, schema)` 辅助函数校验所有请求体。统一错误结构（`{ error, details? }`）和 401/403 的使用规则。
- **状态流转集中管理。** 扩展 `src/lib/*Workflow.ts`，让每个状态机提供 `canTransition(from, to, actor)`。路由直接调用它，而不是各自维护状态列表——"已签协议还能被重新生成"这类 bug 正是由此产生的。
- **共享格式化与界面组件。** 新增 `src/lib/format.ts`（`formatRM`、使用 `Asia/Kuala_Lumpur` 时区的 `formatDate`），每个枚举一个 `StatusPill` 映射，以及通用的 `ProofUploader` 和 `ReviewCard`。
- **可靠的后台任务。** 区块链锚定和邮件改用 Next 的 `after()`，而不是即发即弃的 Promise。在无服务器平台上，响应发送后这些任务可能被立即终止。
- **拆分 `AgreementViewer.tsx`。** 拆为阅读、风险提示、历史和签署审计组件，并完成向深色主题的迁移。

## 3. 能增强项目的产品功能

- **马来语界面。** `src/lib/i18n.ts` 已有完整的英文和马来文词典，`User.language` 也已存储。接入并在个人资料中提供语言切换即可。这是低风险、效果明显的功能。
- **多租约的租客视图。** `/dashboard/tenant/tenancy/[id]` 加一个列表，使续约邀请不会遮住正在进行的租约。
- **房东取消** INVITED 和 PENDING 状态的租约，并自动过期长期 PENDING 的租约。
- **房产编辑**，包括管理员驳回后的重新提交流程。
- **"链上验证"按钮。** `src/lib/blockchain.ts` 中已有 `verifyHashOnChain`。向租客和房东展示存储的哈希与 Sepolia 交易是否一致。
- **租金提醒和逾期通知**，由现有的每日定时任务发送。
- **分页与筛选**，用于房东付款、管理员用户、管理员房产和审计日志。
- **企业住户。** 为已关联的住户提供其租约的只读访问，或移除关联功能。

## 4. 可行性与规模说明

- **AI 成本与延迟。** 协议生成是最慢的路径。Claude Haiku 5.5 是低成本选择；如果协议质量不够，只把 `generateTenancyAgreement` 换成 Claude Sonnet 5.5，其余仍用 Haiku。保留按租约和用户的限流，按 `contentHash` 缓存分析结果，并在界面上显示进度。在 Vercel 上需将生成控制在函数执行时间限制内，或改为后台任务。
- **区块链。** Sepolia 是免费的测试网。对概念验证来说合适，但它不是法律凭证。应将其描述为防篡改证据，并以数据库中的 `contentHash` 为准。
- **法律。** 生成的协议只是草稿。在签署页面加入简短免责声明，并建议由律师审阅，会让项目更可信。
- **个人资料保护（PDPA 2010）。** 保持 KYC 文件私有，在界面中隐藏身份证号的完整内容，并记录保留期限：KYC 图片和已删除用户数据保存多久。
